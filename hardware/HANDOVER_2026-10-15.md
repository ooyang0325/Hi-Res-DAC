## 2. Setup on Windows

**Clone outside OneDrive** (for example `C:\work\Hi-Res-DAC`). OneDrive sync has corrupted `.git` objects
before.

```bash
git config --global core.autocrlf false
git config --global core.longpaths true
git clone https://github.com/ooyang0325/Hi-Res-DAC.git
git checkout codex/schematic-v1.1
```

Set `core.autocrlf false` **before** cloning. CI compares the committed board, schematic and JSON files
byte for byte (`git diff --exit-code`). CRLF conversion would make every gate fail.

**Remotes.** GitHub is `ooyang0325/Hi-Res-DAC`, GitLab is `gitlab.com/ooyang0325/Hi-Res-DAC`. Push to both:
add both push URLs to `origin`, as on the previous machine, or push to each remote.

**KiCad: exactly 10.0.1.** CI uses the `kicad/kicad:10.0.1` image. Another version changes the file
format and the DRC output, and the diff gates fail.
- Put `C:\Program Files\KiCad\10.0\bin` on `PATH`; the scripts find `kicad-cli` through `PATH`.
- Scripts that `import pcbnew` (the generator, the audits, the checks) must run with KiCad's own Python: `"C:\Program Files\KiCad\10.0\bin\python.exe"`.
- Install the packages the scripts need into that Python:

```bash
"C:\Program Files\KiCad\10.0\bin\python.exe" -m pip install numpy openpyxl pyyaml
```

- Set this before running the 3D audits:

```bash
set KICAD10_3DMODEL_DIR=<repo>\hardware\KICAD_STOCK_MODELS
```

**Bash scripts** (`hardware/sim/*/prepare.sh`): run them in Git Bash or WSL.

**Most reliable: run CI exactly as CI does.** Install Docker Desktop, then from the repo root:

```bash
docker run --rm -u root -v "%cd%:/work" -w /work kicad/kicad:10.0.1 bash -c "apt-get update -qq && apt-get install -y -qq python3-yaml && git config --global --add safe.directory /work && HOME=/home/kicad python3 .github/run_gitlab_job.py validate_integrated_audio_study"
```

- Job names are the top-level keys of `.gitlab-ci.yml`: `validate_schematic`, `validate_integrated_audio_study`, and so on.
- A job regenerates its audit JSON files in your working tree. Afterwards, `git diff` shows what changed.
- Files written by the container may be owned by root, so run it inside WSL if that is a problem.

**Other tools.**
- LTspice (native Windows) is needed for sign-off gates G40/G41: `python -m hardware.signoff.run --ltspice "C:\...\LTspice.exe"`.
- Icarus Verilog runs the CPLD testbench (§5.1).

## 3. How the integrated board is produced: read before editing

**The board file is generated. Do not edit it in the KiCad GUI and commit it.**

`hardware/manual_integrated_audio_study.py` replays every engineer decision, recorded in the manifest
`hardware/INTEGRATED_AUDIO_MANUAL_DELTA.json`, onto the source board. It then:
- refills the zones;
- copies the schematic fields, DNP flags and owner-fit exclusions;
- types the footprints;
- writes the silkscreen and the stackup.

Running it again throws away any GUI edit that is not in the manifest. Use KiCad to look, measure and
run DRC; make changes in the manifest, then regenerate:

```bash
"C:\Program Files\KiCad\10.0\bin\python.exe" hardware/manual_integrated_audio_study.py
```

**Manifest fields.** Coordinates are in mm, in KiCad page coordinates (y points down).

| Field | Form | Notes |
| --- | --- | --- |
| `moved_footprints` | `{"C224": [x, y, deg]}` | Absolute position |
| `added_copper` | tracks: `{"kind":"track","net","layer","start_mm","end_mm","width_mm"}`; vias: `{"kind":"via","net","at_mm","diameter_mm","drill_mm"}`, plus `"filled": true, "capped": true` for filled vias | Layer names: `F.Cu`, `PWR` (In2, L3), `SIG` (In3, L4), `B.Cu`. L2 (In1 `GND`) and L5 (In4 `GND5`) are solid planes: no tracks |
| `removed_source_copper` | items of the source board to delete | To undo an added item, delete it from `added_copper` |
| `renamed_pads` | `{"U208": {"7": "N2_LINK_SCK_OUT"}}` | Must match the schematic, or the parity check fails |
| `added_footprints` | `{"R247": {"clone_of": "R224", "value": "33 Ω", "at_mm": [x, y, deg]}}` | Also needs a schematic ECO in `generate_schematic.py` |
| `silk` | `refs` (designator positions) and `texts` (board notes, e.g. the OWNER marks) | Text size 1.0 × 0.15 mm |
| `value_overrides` | `{"R203": "0 Ω"}` | BOM value changes (ECO F12) |

**Rules the checks enforce on new copper.**
- **Clearance and widths:** clearance 0.2 mm; hole clearance 0.28 mm.
- **Via sizes:** Ø0.60/0.20 by default; Ø0.50/0.20 only on the listed slow digital nets; Ø0.70/0.30 or Ø0.80/0.40 for power and thermal.
- **Vias near pads:** a via that touches an SMD pad, or comes within 0.10 mm of one, must be filled and capped.
- **No right-angle bends:** CI checks bends, so chamfer corners at 45°.
- **Footprint gaps:** footprint bounding boxes, including courtyard line width, must not overlap. This is stricter than KiCad's courtyard check.
- **Blocked areas:**
  - no B.Cu copper inside the J701 courtyard;
  - high-impedance protection nodes keep away from the clocks (DRU rules);
  - N6_MCK_RC (the 1 MΩ hold node) stays one via-free F.Cu track.

**Not in the repository.** The previous engineer's macOS helpers live outside the repo, in
`~/dac_layout_work`: a 45° router, a block builder that patched the manifest, a decoupling-cap site
search, a silk-legend placer, and archived change blocks. Manifest edits are enough for small changes.
Ask the owner if you need those tools.

**Things that bite.**
- **KiCad rewrites `.kicad_pro` when it opens a board.** Revert it before every commit: `git checkout -- hardware/*.kicad_pro`.
- **Shared libraries stay untyped.** The integrated board gives every BOM footprint an SMD/THT type, but `JLC_Imported.pretty` and `DAC_HPA.pretty` stay untyped, because the frozen study boards are checked against them. So KiCad reports 86 `lib_footprint_mismatch` warnings. `check_integrated_audio_study.py` accepts each one only when the library copy, given the board's type, matches exactly; `check_integrated_parity.py` types a scratch copy of the libraries. Do not edit the shared libraries until the planned library cleanup (§5.6).
- **Library or schematic changes ripple.** `place_board.py` builds boards from the schematic netlist. Changing a footprint ID or a library footprint can break the frozen study boards' CI jobs.

## 5. Remaining work, in order

### 5.1 OD-16: CPLD fit in AGM Supra (Windows; before the PCBA order)

**Status, 15 Oct: closed.** The fit closes at 36 MHz (setup +8.98 ns, hold +0.29 ns; LINK_SCK on a global
clock network). The testbench passes on the edited RTL and on Supra's routed netlist. It used Supra's
native flow, `cpld/run_supra_fit.sh`, because Quartus 15.0 needs the NTU licence server. Results and
the four changes the fit needed are in [cpld/README.md](cpld/README.md#fit-result-15-oct-2026). The
steps below remain the Quartus route.

LINK_SCK (36 MHz) enters U202 on pin 9, which is not a global-buffer pin. The fit must show:
1. LINK_SCK on a global or clock network;
2. setup and hold closed at 36 MHz with margin;
3. audio data crossing into FAM_CLK only through the FIFO.

Everything except the fit is ready in [cpld/](cpld/README.md):
- `link_fit_skeleton.v`: the skeleton design;
- `U202_pins.asf`: the pin assignments;
- `link_fit.sdc`: the timing constraints;
- a testbench that passes.

Steps:
1. Install AGM's Supra package with the Quartus version it specifies.
2. Re-run the testbench first:

   ```bash
   cd hardware/cpld
   iverilog -g2012 -o link_tb link_fit_skeleton.v link_fit_skeleton_tb.v && vvp -n link_tb
   ```

   It must print `PASS`.
3. Synthesize `link_fit_skeleton.v` in Quartus for the device AGM names for the AGRV2K flow. Run Supra with the `.asf` and `.sdc`.
4. If Supra rejects an assignment name (the drive and slew lines for pins 13 and 28), use Supra's own name. Keep the intent: ≤ 8 mA or slow slew.
5. Record the following in `cpld/README.md` and in the v1.1 response, §4:
   - the network LINK_SCK lands on;
   - the worst setup and hold slack at 36 MHz;
   - the drive and slew applied to pins 13 and 28.
6. **If it does not close at 36 MHz**, the fallback is an 18 MHz link. That limits the board to 192 kHz until a board revision. Record it as a limitation. The board ships either way.

**For the product RTL.** It is not in the repository. The skeleton does not flush the FIFO when I²S
starts again after a mid-frame stop, so channels can swap. The real design must flush the FIFO, or
realign L/R, on the rising edge of I2S_RUN.

### 5.3 OD-15: X201 sample measurement (bench; owner's samples)

Keep X201 = Kyocera KC2520K80.0000C1GE00 (≤ 1 ps phase jitter). Test it before the PCBA release:
- **Samples:** two parts, at 3.3 V into a 15 pF load, on a scope of ≥ 1 GHz.
- **Record:** 10–90 % rise and fall times, and the duty at 1.2, 1.65 and 2.05 V.
- **Pass:** duty 45–55 % at all three thresholds, on both samples.
- **If a sample fails:** measure two SiT8208AI-…-33S-80.000000 samples the same way. Change X201 only if those pass, and record the trade: MEMS close-in phase noise against duty margin.
- **At bring-up:** duty at U301 XI must be 45–55 % (OD-6). Re-fit 33 Ω at R203 only if XI rings.
